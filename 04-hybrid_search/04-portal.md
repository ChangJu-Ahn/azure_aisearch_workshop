# 4️⃣ 하이브리드 검색 – Azure 포털에서 직접 해보기 (No-Code Guide)

> 🎯 **이 문서의 목적**
> 앞선 노트북 실습은 **코드**로 키워드(BM25)와 벡터 검색을 동시에 실행하고, RRF로 결과를 합쳤습니다.
> 같은 하이브리드 검색을 **Azure 포털 화면(UI)** 에서, 별도 코드 없이 **검색 탐색기**로 실행할 수 있습니다.

---

## 📌 한눈에 보기: 코드 vs 포털

| 단계 | 노트북(코드)에서 한 일 | 포털(화면)에서 하는 방법 |
|------|----------------------|------------------------|
| 사전 준비 | 키워드 인덱스 + 벡터 필드(`content_vector`) | 2·3번 가이드대로 인덱스/벡터 구성 (그대로 재사용) |
| 하이브리드 검색 | `search_text` + `vector_queries` 를 한 번에 호출 | **검색 탐색기**에서 텍스트 + 벡터 쿼리를 함께 입력 |
| 결과 통합 | Azure가 **RRF(k=60)** 로 자동 결합 | 포털도 동일하게 **RRF 로 자동 결합** |

> 💡 하이브리드 검색은 **별도 설정이 거의 필요 없습니다.** 검색 요청에 **텍스트 검색어**와 **벡터 쿼리**를 **동시에** 주면, Azure AI Search가 자동으로 두 결과를 RRF로 합쳐줍니다.

---

## 0. 시작 전 준비

하이브리드 검색은 **키워드 + 벡터**를 합치는 것이므로, 다음이 모두 준비돼 있어야 합니다:

- ✅ 키워드 검색용 필드 (`title`, `brand`, `category`, `normal_price` …) → **2번 가이드**
- ✅ 벡터 필드 (`content_vector`, 3072차원, HNSW/cosine) → **3번 가이드**

> 즉, **3번(벡터) 가이드까지 마친 동일 인덱스**(`products-index`)를 그대로 사용하면 됩니다. 새로 만들 것이 없습니다.

> 📸 **[이미지 첨부]** products-index 의 필드 목록에 텍스트 필드 + content_vector 가 함께 있는 화면

---

## 1. 하이브리드 검색 원리 (포털에서도 동일)

노트북에서 본 **RRF(Reciprocal Rank Fusion)** 가 포털 검색에도 그대로 적용됩니다.

```
RRF 점수 = 1/(60 + 키워드_순위) + 1/(60 + 벡터_순위)
```

- 키워드 검색과 벡터 검색 **양쪽에서 골고루 높은 순위**를 받은 상품이 최종 상위로 올라갑니다.
- **k=60** 은 Azure AI Search에 고정되어 있어 따로 설정할 필요가 없습니다.

---

## 2. 검색 탐색기에서 하이브리드 검색 (코드: `01-hybrid_search.ipynb` 대체)

1. **Azure AI Search 리소스 > 검색 탐색기(Search explorer)** 를 엽니다.
2. 인덱스가 `products-index` 인지 확인합니다.
3. **JSON / 쿼리 보기**로 전환합니다.

### 2.1 기본 하이브리드 쿼리

검색어(`search`)와 벡터 쿼리(`vectorQueries`)를 **함께** 넣는 것이 핵심입니다.
(통합 벡터화로 인덱스를 만들었다면 `kind: "text"` 로 자연어만 넣으면 자동 임베딩됩니다.)

```json
{
  "search": "노스페이스 가볍고 방수되는 자켓",
  "vectorQueries": [
    {
      "kind": "text",
      "text": "노스페이스 가볍고 방수되는 자켓",
      "fields": "content_vector",
      "k": 50
    }
  ],
  "top": 10
}
```

- `search` → **키워드(BM25)** 검색을 담당 (정확한 브랜드/모델명에 강함)
- `vectorQueries` → **벡터(의미)** 검색을 담당 (자연어/유의어에 강함)
- Azure가 두 결과를 **RRF로 자동 결합**해 `@search.score` 로 정렬해 반환합니다.

> 📸 **[이미지 첨부]** 검색 탐색기 JSON 보기에 하이브리드 쿼리를 입력한 화면

> 📸 **[이미지 첨부]** 하이브리드 검색 결과(@search.score 포함)가 나온 화면

### 2.2 실무 검색 시나리오로 테스트

노트북의 10가지 시나리오를 화면에서 그대로 테스트해 보세요. `search` 와 `text` 에 같은 문장을 넣으면 됩니다.

| # | 시나리오 | 입력 문장 |
|---|----------|----------|
| 1 | 브랜드 + 의미 | 노스페이스 가볍고 방수되는 자켓 |
| 2 | 정확한 용어 + 자연어 | 압소바 신생아 선물 |
| 5 | 가격대 + 니즈 | 3만원대 출산선물 |
| 9 | 시즌 + 카테고리 | 여름 러닝화 |

> 📸 **[이미지 첨부]** 시나리오별 하이브리드 검색 결과 비교 화면

### 2.3 (선택) 벡터 가중치 조절

노트북의 `weight` 파라미터처럼, 포털 JSON에서도 벡터 검색 비중을 조절할 수 있습니다.

```json
{
  "search": "압소바 신생아 선물",
  "vectorQueries": [
    {
      "kind": "text",
      "text": "압소바 신생아 선물",
      "fields": "content_vector",
      "k": 50,
      "weight": 0.7
    }
  ],
  "top": 10
}
```

| weight 값 | 의미 |
|-----------|------|
| 0.0 | 키워드 위주 |
| 0.5 | 키워드/벡터 균형 (기본) |
| 0.7~0.8 | 벡터(의미) 위주 |

> 📸 **[이미지 첨부]** weight 값을 바꿔가며 결과가 달라지는 비교 화면

## 3. 검색 방법 비교 직접 체험하기

같은 검색 문장으로 세 가지를 번갈아 실행해 차이를 눈으로 확인해 보세요.

| 검색 방법 | 검색 탐색기 입력 방법 |
|----------|---------------------|
| 키워드만 | `search` 만 입력, `vectorQueries` 제거 |
| 벡터만 | `search` 를 `null` 로, `vectorQueries` 만 입력 |
| 하이브리드 | `search` + `vectorQueries` **둘 다** 입력 |

> 📸 **[이미지 첨부]** 키워드 / 벡터 / 하이브리드 결과를 나란히 비교한 화면

## ✅ 기획자용 체크리스트

- [ ] 2·3번 가이드로 만든 `products-index`(텍스트 + 벡터) 재사용 확인
- [ ] 검색 탐색기 JSON 보기에서 `search` + `vectorQueries` 동시 입력
- [ ] 하이브리드 결과가 RRF로 자동 결합됨을 확인
- [ ] (선택) weight 값을 바꿔 키워드/벡터 비중 조절
- [ ] 키워드 / 벡터 / 하이브리드 결과 차이 비교

## 💡 정리

| 결론 | 설명 |
|------|------|
| **추가 인프라 불필요** | 기존 텍스트+벡터 인덱스에 검색 요청만 합쳐 보내면 끝입니다. |
| **RRF 자동 결합** | 포털도 노트북과 동일하게 k=60 RRF로 결과를 합칩니다. |
| **프로덕션 권장 검색** | 정확한 용어와 자연어를 모두 잡아내, 실무에서 가장 추천되는 방식입니다. |
